esql-from-exclusions: ES|QL `FROM a*,-a1` fails to parse in es-mini (each source is read as an identifier, es-query/src/esql.rs ident_list) where Elasticsearch 9.5.5 excludes a1. Accept a leading `-` on FROM sources in the parser and pass the expression to the existing index resolution (es_index::aliases), which already handles exclusions; match ES's results and its errors for an exclusion matching nothing and for an exclusion alone, verified against ES 9.5.5. Add es-query/tests/esql_from_exclusions.rs. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-query --test esql_from_exclusions`
non-compound-segments: es-codec reads only compound (.cfs/.cfe) segments, but Lucene writes non-compound segments when a merged segment exceeds TieredMergePolicy's noCFSRatio, so a larger Elasticsearch 9.5.5 index can fail to open in es-mini. Read non-compound segments (the same files outside a .cfs), and write them where es-mini's merges would as Lucene does, checked byte-for-byte against Lucene 10.5.1 source (skill: port-lucene-format). Record an ES 9.5.5 data directory with a non-compound segment (e.g. index.compound_format: false) under a NEW fixture directory with a generator script, never touching fixtures/es-9.5.5/ or fixtures/expected/, and add es-codec/tests/non_compound_segments.rs reading it. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-codec --test non_compound_segments`
