# Ordered goals for the Ralph loop's `goals` suite. One line each; an iteration deletes a line
# only when that goal's done-criteria hold. The loop then runs the line's Done-check itself and
# rejects the iteration if it fails. Later goals assume earlier ones are done.
aggs-histograms: histogram and date_histogram (interval, calendar_interval, fixed_interval, offset, time_zone, min_doc_count, extended_bounds, hard_bounds, keyed, format). Like ES, fail with too_many_buckets_exception past search.max_buckets (65,536) instead of allocating them. Done-check: `! grep -qE '^aggregations/(date_)?histogram.yml/' tests/yaml-xfail.txt`
aggs-ranges-filters: range, date_range, filter, filters, missing and global aggregations. Done-check: `! grep -qE '^aggregations/(range|date_range|filter|filters_bucket|missing|global).yml/' tests/yaml-xfail.txt`
aggs-top-hits-typed-keys: top_hits (size, sort, _source filtering) and typed_keys across every supported aggregation. Done-check: `! grep -qE '^aggregations/(top_hits|typed_keys).yml/' tests/yaml-xfail.txt`
flush-on-shutdown: es-mini handles SIGTERM/SIGINT with axum graceful shutdown, then flushes (commits segments, empties the translog) before exiting, so a clean stop leaves a directory Elasticsearch opens without replay. Add an es-mini/tests/persist.rs test named `graceful_shutdown_flushes` (drive the shutdown future directly). Done-check: `cargo test -p es-mini --test persist graceful_shutdown_flushes`
real-deflate: inflate::frame writes stored (uncompressed) DEFLATE blocks and inflate decodes bit by bit; add real compression for SMILE/state files and table-driven decoding. Done-check: `cargo test -p es-codec && scripts/cross_engine_rust.sh`
unsupported-codecs: indices in codecs es-codec cannot read (e.g. Zstd stored fields, ES812Postings `_id`) are silently left out of disk::open; read them (port Zstd decompression without a new crate, ES812Postings) or fail with a clear error per index. Add a test with an Elasticsearch-written index using index.codec=best_compression. Done-check: `cargo test -p es-codec && cargo test -p es-index`
unreadable-segments: documents whose segment cannot be read are skipped or reported missing (es-index lib.rs get/docs_at/take); surface a corrupt segment as an error on open instead. Add a test named `a_corrupt_segment_fails_open`. Done-check: `cargo test -p es-index a_corrupt_segment_fails_open`
index-sorting: indices with index.sort.* fail to open (segment_infos rejects index sorts); read sorted segments. Done-check: `cargo test -p es-codec`
nested-dynamic-mapping: dynamic mapping covers top-level fields only (mapping.rs map_dynamic); map object fields recursively (properties of objects, dotted names), and add numeric_detection/date_detection settings. Add YAML-equivalent tests in es-index. Done-check: `cargo test -p es-index && cargo test -p es-mini --test yaml && scripts/cross_engine_fields.sh`
date-semantics: dates match and sort as their JSON strings (es-query resolve: Date => Keyword); only range parses instants, the mapping's `format` is ignored by parse_date_millis, range time_zone is accepted and ignored, and `now`/date math is unsupported. Implement ES date semantics for term/sort/range (format, time_zone, date math, `uuuu`). Done-check: `cargo test -p es-query && cargo test -p es-mini --test yaml`
missing-queries: add match_phrase, match_phrase_prefix, multi_match and query_string (quoting, ranges, boolean operators, escapes) to the query DSL (es-query parse.rs; parse_query_string is whitespace-only), each verified against Elasticsearch 9.5.5 responses. Done-check: `cargo test -p es-query && cargo test -p es-mini --test yaml`
constant-score-boost: constant_score ignores boost (score always 1.0); apply boost there and in every query that takes one. Done-check: `cargo test -p es-query`
settings-validation: PUT _settings checks only index.codec as static and only top-level index.* names; reject every static setting on open indices (number_of_shards, ...) and validate nested setting groups and values like Elasticsearch; GET _settings include_defaults returns all defaults it models; list-valued settings expand as ES's list settings, and a leaf that is also a branch (`a` and `a.b`) is rejected. Done-check: `cargo test -p es-mini && cargo test -p es-mini --test yaml && cargo test -p es-index`
auto-id-format: auto-generated ids are time+counter hex; generate Elasticsearch's 20-character base64 time-based UUIDs (TimeBasedUUIDGenerator) and pass autoGeneratedIdTimestamp in translog operations. Done-check: `cargo test -p es-mini && cargo test -p es-codec --test translog`
alias-date-math: resolve_date_math supports only `anchor||/d{fmt}` with yyyy/MM/dd; support `now` and every rounding unit and format like Elasticsearch's DateMathExpressionResolver, for index names as well as alias names. Done-check: `cargo test -p es-mini`
refresh-interval: only refresh_interval=-1 delays visibility; honor positive refresh intervals (writes searchable after the interval or an explicit refresh), matching Elasticsearch's YAML refresh tests. Done-check: `cargo test -p es-mini --test yaml && cargo test -p es-index`
multi-index-esql-types: ES|QL keeps the first index's type when indices disagree; report `unsupported` like Elasticsearch, and give documents_found/values_loaded real counts instead of assuming top-N pushdown. Done-check: `cargo test -p es-query --test esql && cargo test -p es-mini --test fixture_parity`
esql-errors-grammar: ES|QL parse and verification errors use Elasticsearch's messages and types (review finding D33), and dynamic strings get every multi-field the mapping declares, not only `keyword`. Done-check: `cargo test -p es-query --test esql`
per-index-locks: one global RwLock covers all indices and persistence holds it as a write lock during fsync; use per-index locks so writes to different indices and reads proceed concurrently, keeping saves serialized per data directory. Done-check: `cargo test --workspace && cargo test -p es-mini --test persist`
tidy-review-refactors: the cosmetic refactors review findings M-C6, M-C7, M-Q1, M-Q5, M-S3, M-S4 and M-S6 left (FieldInfo literals in disk.rs and data_dir, parallel slices in segment writers, splitting es-query lib.rs, settings-name constants), each as its own commit with no behavior change. Done-check: `scripts/check.sh`
test-scratch-cleanup: tests leave scratch directories in the temp dir (esm-save-*, esm-persist-*, esm-disk-meta-*, esm-incr-*, esm-tlog-*); remove them when each test ends (a drop guard), without new crates. Done-check: `rm -rf /tmp/esm-save-* /tmp/esm-persist-* /tmp/esm-disk-meta-* /tmp/esm-incr-* /tmp/esm-tlog-* && cargo test --workspace -q && ! ls -d /tmp/esm-save-* /tmp/esm-persist-* /tmp/esm-disk-meta-* /tmp/esm-incr-* /tmp/esm-tlog-* 2>/dev/null`
perf-small-ceilings: the remaining marked performance ceilings, each measured before and after with bench/run.sh (allowed for performance goals) or a focused test: field_by_number linear scan (segment.rs), compound sub-files read whole instead of mmap (es-codec lib.rs), bit-by-bit inflate. Done-check: `scripts/check.sh`
esql-parity-harness: fixtures/generate_esql.sh records real Elasticsearch 9.5.5 responses to a fixed ES|QL query set (fixtures/esql-queries.txt, one query per line) over a dataset it ingests (Docker 1 CPU / 1 GB, docker exec, container always removed; output in fixtures/expected-esql/, never touching fixtures/es-9.5.5 or fixtures/expected), and es-mini/tests/esql_parity.rs replays the same ingest in memory and compares every response (columns, values, and error types for invalid queries), with known differences in fixtures/esql-parity-xfail.txt (may only shrink). Seed the query set with queries for every command and function in PLAN.md's ES|QL list, so later goals are measured against it. Done-check: `test -s fixtures/esql-queries.txt && ls fixtures/expected-esql/*.json >/dev/null && cargo test -p es-mini --test esql_parity`
esql-source-commands: ES|QL `ROW`, `SHOW INFO`, `FROM` with index patterns and comma lists, and `METADATA _id, _index, _version`. Done-check: `cargo test -p es-mini --test esql_parity && ! grep -qiE '^(row|show|from.*metadata)' fixtures/esql-parity-xfail.txt`
esql-eval-functions: ES|QL `EVAL` and `RENAME`, and an expression engine with ES|QL's type rules (integer/long/double/keyword/text/boolean/date/null, implicit casts, multi-values) used by `WHERE` and `EVAL`: arithmetic, comparison, `LIKE`, `RLIKE`, `IN`, `IS NULL`, `CASE`, `COALESCE`, string functions (`CONCAT`, `LENGTH`, `SUBSTRING`, `TO_LOWER`, `TO_UPPER`, `TRIM`, `STARTS_WITH`, `ENDS_WITH`), math (`ABS`, `ROUND`, `FLOOR`, `CEIL`, `POW`), date (`DATE_EXTRACT`, `DATE_FORMAT`, `DATE_TRUNC`, `NOW`), conversions (`TO_STRING`, `TO_INTEGER`, `TO_LONG`, `TO_DOUBLE`, `TO_BOOLEAN`, `TO_DATETIME`) and multi-value basics (`MV_COUNT`, `MV_MIN`, `MV_MAX`). Done-check: `cargo test -p es-query --test esql && cargo test -p es-mini --test esql_parity && ! grep -qiE '\b(eval|rename)\b' fixtures/esql-parity-xfail.txt`
esql-stats: ES|QL `STATS ... BY` with `COUNT`, `COUNT_DISTINCT`, `AVG`, `SUM`, `MIN`, `MAX`, `MEDIAN`, `PERCENTILE`, `VALUES` and `BUCKET` (numeric and date), grouping by several columns and expressions, reusing the aggregation code from the aggs-* goals where it fits. Done-check: `cargo test -p es-mini --test esql_parity && ! grep -qiE '\bstats\b' fixtures/esql-parity-xfail.txt`
