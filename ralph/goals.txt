# Ordered goals for the Ralph loop's `goals` suite. One line each; an iteration deletes a line
# only when that goal's done-criteria hold. The loop then runs the line's Done-check itself and
# rejects the iteration if it fails. Later goals assume earlier ones are done.
shard-routing: today every index has exactly one shard and number_of_shards is only stored. Port Elasticsearch 9.5.5's document routing (murmur3 hash of _routing or _id, with routing_num_shards and routing_factor, as in OperationRouting/IndexRouting) into es-index as a pure function from (id, routing, number_of_shards, routing_num_shards) to shard number. Verify it against expected values taken from real ES 9.5.5 (skill: verify-with-elasticsearch), stored in a NEW fixture file; never regenerate fixtures/expected/. Nothing else changes: behavior stays single-shard. Done-check: `nice -n 19 cargo test -j 2 --locked -p es-index --test shard_routing`
shard-storage: give each index N independent shard stores (documents, segments, translog) instead of one, with the on-disk layout <index>/0..N-1/ as in ES. disk::open must still load existing single-shard data directories, and every save must keep the durability properties in AGENTS.md (no half-written directory, never drop data). number_of_shards=1 output must stay byte-identical. Depends on shard-routing. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-index --test shard_storage`
shard-writes: route index, create, update, delete and bulk to the owning shard using the routing function; honor the routing parameter and _routing metadata. _version, _seq_no and _primary_term become per-shard, and flush covers all shards. Depends on shard-storage. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test shard_writes`
shard-search-merge: search every shard separately and merge: top-N with ES's tie-break (score, then shard index, then doc id), the reduce step for aggregations including terms doc_count_error_upper_bound and shard_size, and from/size, search_after, scroll and PIT across shards. Per-shard BM25 statistics as in ES's default query_then_fetch; dfs_query_then_fetch uses global statistics. Add parity fixtures from real ES 9.5.5 for a 3-shard index in a NEW file; never regenerate fixtures/expected/. Depends on shard-writes. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test shard_parity`
shard-responses: report real shard counts: _shards.total/successful/failed with per-shard failures, _cluster/health and per-index health at level=shards, profile shard ids, and _cat/shards and _stats. Remove the "every index has one shard" ponytail comments in es-mini/src/search.rs and es-mini/src/lib.rs. Depends on shard-search-merge. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test shard_responses`
security-authn: add opt-in security through the xpack.security.enabled setting, as in ES (default false, so existing tests and fixtures are unchanged). When on, every request needs `Authorization: ApiKey base64(id:key)` or HTTP basic auth as the built-in `elastic` superuser, whose password comes from a setting as ES's ELASTIC_PASSWORD bootstrap does (hashed at rest, never logged), and failures return ES's exact 401 body and WWW-Authenticate headers. Add GET /_security/_authenticate. Key secrets are stored hashed as ES does, never in plain text. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test security_authn`
security-api-keys: implement the API key lifecycle as in ES 9.5.5: POST/PUT /_security/api_key (name, expiration, metadata, role_descriptors), GET /_security/api_key and POST /_security/_query/api_key, DELETE /_security/api_key (invalidate), PUT /_security/api_key/{id} and _bulk_update. POST /_security/api_key/grant is out of scope (elastic is the only user). Expired and invalidated keys fail authentication. Keys persist across restarts through es_index::disk with the durability rules in AGENTS.md in a hidden system index named as in ES 9.5.5 (.security-7 behind the .security alias), stored as ordinary documents through the existing translog and segment code. Like ES, the index is excluded from wildcard expressions and _cat output, and only the security APIs can read or write it, not ordinary document or search requests. Response bodies match real ES, checked with verify-with-elasticsearch. Depends on security-authn. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test security_api_keys`
security-authz: enforce role_descriptors: cluster privileges and index privileges (names and wildcard patterns, including aliases and data streams resolved through es_index::aliases) for each REST action, mapped to ES's action names and privilege groups (read, write, index, create_index, manage, monitor, all, ...). A key created by another key is limited to its creator's privileges (limited_by) as in ES. Denials return ES's 403 security_exception body. Add GET/POST /_security/user/_has_privileges for keys. Field- and document-level security (field_security, query in index privileges) are out of scope: a role descriptor that uses them is rejected rather than silently ignored, with the response ES 9.5.5 gives when the feature is unavailable (check with verify-with-elasticsearch; if ES accepts it, record the difference in ralph/NEEDS_HUMAN.md). Depends on security-api-keys. Done-check: `scripts/check.sh && nice -n 19 cargo test -j 2 --locked -p es-mini --test security_authz`
security-yaml: enable the vendored ES YAML tests for the security API key APIs that the above goals cover, without editing vendored tests or their runner (PREREQUISITE, human only: tests/yaml has no security directory today, and vendoring ES's security YAML tests into tests/yaml/security must happen before this goal runs; if it is missing, record that in ralph/NEEDS_HUMAN.md and stop). Escalate tests that need features out of scope in ralph/NEEDS_HUMAN.md. Depends on security-authz. Done-check: `test -d tests/yaml/security && scripts/check.sh && YAML_FILTER=security nice -n 19 cargo test -j 2 --locked -p es-mini --test yaml`
