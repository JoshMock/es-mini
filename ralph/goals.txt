# Ordered goals for the Ralph loop's `goals` suite. One line each; an iteration deletes a line
# only when that goal's done-criteria hold. The loop then runs the line's Done-check itself and
# rejects the iteration if it fails. Later goals assume earlier ones are done.
esql-perf-100k: ES|QL is about 10x slower than Elasticsearch at 100k documents (bench/RESULTS.md: esql 232 ms vs 19 ms, esql_stats 199 vs 24, esql_eval 198 vs 22), while it beat Elasticsearch at 10k, so its cost grows with the document count. Work as a measured loop, many rounds per iteration: (1) read ralph/PERF_NOTES.md (git-ignored, kept across rollbacks) for hypotheses already tried; (2) find where the time goes at 100k documents (time the phases of a release es-mini serving the bench data, or use a profiler if one is installed); candidates include the after-bench ES|QL markers in ralph/ponytail-ledger.md (per-row parsing, linear group lookup, no LIMIT pushdown or early stop, no predicate rewriting); (3) state one hypothesis, make the smallest change that tests it, and run `bench/ab.sh $(cat ralph/.iteration-start)` (the commit this iteration started from); (4) commit only a change that passes, with the hypothesis and ab.sh's table in the commit message, and revert one that does not; (5) append the hypothesis, the change and ab.sh's numbers to ralph/PERF_NOTES.md either way. Results must not change: keep every ES|QL test and parity check passing. Never edit bench/. Done-check: `MAX_MS=40 bench/ab.sh HEAD`. Gate: `bench/ab.sh $START`
